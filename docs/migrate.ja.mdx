---
title: "Waffo Pancake への移行"
description: "pancake-migrate CLI で商品・価格（移行元により Webhook・ブランディング・割引コードも）を Waffo Pancake に移行"
---

すでに Stripe、Creem、Dodo Payments、Lemon Squeezy を運用していますか？ [`@waffo/pancake-migrate`](https://www.npmjs.com/package/@waffo/pancake-migrate) CLI は、商品と価格を Waffo Pancake ストアにコピーします（Stripe からは Webhook とブランディング、Lemon Squeezy からは割引コードも）。手入力での再登録は不要です。

<Note>
移行されるのは**カタログと設定**であり、稼働中の課金ではありません。アクティブなサブスクリプション・顧客・支払い方法はそのままの場所に残ります。理由と対処については [移行されないもの](#what-does-not-migrate) を参照してください。
</Note>

<Info>
他のプラットフォームをご利用ですか？現在 **Stripe**、**Creem**、**Dodo Payments**、**Lemon Squeezy** からの移行に対応しており、対応プラットフォームは順次拡大予定です。[お問い合わせ](mailto:support@waffo.ai)いただき、移行元のプラットフォームをお知らせください。優先的に対応します。
</Info>

## 概念のマッピング

何かを実行する前に、既存のセットアップが Waffo Pancake とどう対応するかを確認しておきましょう。このマッピングは CLI が自動で処理します。この表は、何が起きるかを把握するためのものです。

| Stripe / Creem | Waffo Pancake | 備考 |
|---|---|---|
| Product + Price | 1 つの商品（`prices` を含む） | Pancake は価格を商品に統合します。Stripe のマルチ通貨価格は保持されます。Creem は単一通貨です。 |
| Recurring interval | `billingPeriod` | `week`→`weekly`、`month`→`monthly`、3 か月ごと→`quarterly`、`year`→`yearly`。 |
| Webhook endpoint | ストア Webhook | Stripe のエンドポイントは URL + イベントタイプのマッピングとともに移行されます。（Creem の Webhook は CLI では読み取りません。） |
| Account branding | ストアブランディング | Stripe のサポートメール + Web サイトが移行されます。 |
| Tax behavior | `taxCategory` | Creem のカテゴリは自動的にマッピングされます。Stripe では `--tax-category` で 1 つのデフォルトを指定します。 |
| Test / live keys | `test` / `production` | キーのプレフィックスから自動検出されます（`sk_test_`→test、`sk_live_`→production）。読み取る Stripe データと書き込む Webhook 設定が決まります。商品は常に未公開のテスト版として作成されます。 |

## 始める前に

3 つのものが必要です。

1. **Node.js 18+**
2. **Waffo Pancake API キー** — Merchant ID（`MER_...`）と RSA 秘密鍵。[Dashboard → API & Development](https://pancake.waffo.ai/merchant/dashboard/integration) で作成できます。キーの扱い方は [SDK ガイド](/ja/integrate/skill) を参照してください。
3. **移行元プラットフォームのキー** — Stripe Secret Key（`sk_test_...` / `sk_live_...`）、Creem API Key（`creem_test_...` / `creem_...`）、Dodo Payments API キー、または Lemon Squeezy API キー。

<Warning>
移行元の test / live どちらのデータを読む場合でも、移行は Pancake ストアに未公開のテスト版として商品を**作成**します。何が作成されるかを正確にプレビューするため、必ず最初に `--dry-run` を実行してください。
</Warning>

## 最短ルート: インタラクティブモード

```bash
npx @waffo/pancake-migrate
```

ステップごとにガイドします。

<Steps>
  <Step title="移行元を選択">
    Stripe、Creem、Dodo Payments、Lemon Squeezy のいずれか。
  </Step>
  <Step title="移行先ストアを選択">
    既存のストアを選ぶか、その場で新規作成します。
  </Step>
  <Step title="プレビュー">
    何かが作成される前に、移行される内容を正確に確認します。
  </Step>
  <Step title="移行">
    商品と価格がストアに作成されます。Stripe からは Webhook とブランディング、Lemon Squeezy からは割引コードも作成されます。Lemon Squeezy と、税込または税設定が未指定の Dodo 価格では、先に移行先の税の扱いを確認したことを承認します。
  </Step>
</Steps>

## スクリプトによる移行

すべてをフラグで渡したい場合（CI や実行の繰り返し向け）は、移行元ごとのサブコマンドを使います。ターミナルのない環境（CI など）では、確認プロンプトを省略する `--yes` を追加します。

### Stripe から

```bash
# Full migration (products + webhooks + branding)
npx @waffo/pancake-migrate stripe \
  --stripe-key sk_test_xxx \
  --merchant-id MER_xxx \
  --private-key ./private.pem \
  --store-id STO_xxx \
  --tax-category saas
```

まず `--dry-run` でプレビューします。

```bash
npx @waffo/pancake-migrate stripe \
  --stripe-key sk_test_xxx \
  --merchant-id MER_xxx \
  --private-key ./private.pem \
  --store-id STO_xxx \
  --tax-category saas \
  --dry-run
```

ストアがまだない場合は、`--store-id new` を渡して移行中に作成します。

```bash
npx @waffo/pancake-migrate stripe \
  --stripe-key sk_test_xxx \
  --merchant-id MER_xxx \
  --private-key ./private.pem \
  --store-id new \
  --store-name "My store" \
  --tax-category saas
```

不要なステップは `--skip-products`、`--skip-webhooks`、`--skip-branding` でスキップします。

```bash
npx @waffo/pancake-migrate stripe ... --skip-webhooks --skip-branding
```

**Stripe フラグ**

| Flag | 説明 |
|---|---|
| `--stripe-key <key>` | Stripe Secret Key（`sk_test_...` または `sk_live_...`） |
| `--merchant-id <id>` | Pancake Merchant ID（`MER_...`） |
| `--private-key <path>` | Pancake API 秘密鍵ファイルへのパス、または生のキー内容 |
| `--store-id <id>` | 移行先 Store ID（`STO_...`）、または `new` で新規作成 |
| `--store-name <name>` | 新規ストアの名前（`--store-id new` の場合は必須） |
| `--tax-category <cat>` | デフォルトの税カテゴリ: `saas`、`digital_goods`、`software`、`ebook`、`online_course`、`consulting`、`professional_service` |
| `--dry-run` | 何も作成せずにプレビュー |
| `--yes` | 確認プロンプトをスキップ |
| `--skip-products` | 商品の移行をスキップ |
| `--skip-webhooks` | Webhook の移行をスキップ |
| `--webhook-url <url>` | Stripe のエンドポイントが複数ある場合に移行するものを指定（Pancake は環境ごとに Webhook URL を 1 つだけ保持します） |
| `--skip-branding` | ブランディングの移行をスキップ |

### Creem から

```bash
npx @waffo/pancake-migrate creem \
  --api-key creem_test_xxx \
  --merchant-id MER_xxx \
  --private-key ./private.pem \
  --store-id STO_xxx
```

まずプレビューします。

```bash
npx @waffo/pancake-migrate creem \
  --api-key creem_test_xxx \
  --merchant-id MER_xxx \
  --private-key ./private.pem \
  --store-id STO_xxx \
  --dry-run
```

**Creem フラグ**

| Flag | 説明 |
|---|---|
| `--api-key <key>` | Creem API Key（`creem_test_...` または `creem_...`） |
| `--merchant-id <id>` | Pancake Merchant ID（`MER_...`） |
| `--private-key <path>` | Pancake API 秘密鍵ファイルへのパス、または生のキー内容 |
| `--store-id <id>` | 移行先 Store ID（`STO_...`）、または `new` で新規作成 |
| `--store-name <name>` | 新規ストアの名前（`--store-id new` の場合は必須） |
| `--dry-run` | 何も作成せずにプレビュー |
| `--yes` | 確認プロンプトをスキップ |

### Dodo Payments から

`DODO_PAYMENTS_API_KEY` を安全に設定し、まずプレビューします（Waffo の認証情報は不要です）。

```bash
npx @waffo/pancake-migrate dodo --environment test --dry-run
```

書き込む場合は `--dry-run` を外し、Pancake の認証情報を追加します。

```bash
npx @waffo/pancake-migrate dodo --environment test \
  --merchant-id MER_xxx \
  --private-key ./private.pem \
  --store-id STO_xxx \
  --acknowledge-tax-semantics
```

税込または税設定が未指定の価格では `--acknowledge-tax-semantics` が必要です。移行先の税の扱いを確認したことを示すもので、Waffo の税設定は変更しません。ターミナルではプロンプトで承認することもできます。ターミナルのない環境（CI など）で実行する場合は、最終確認を省略する `--yes` も追加します。`--yes` は税の確認の代わりにはなりません。`--store-id new --store-name "My store"` で承認後にストアを作成できます。本番の Dodo 商品を読む場合は `--environment live` を明示します。キーの接頭辞から環境を推測しません。

### Lemon Squeezy から

`LEMONSQUEEZY_API_KEY` を安全に設定し（テストモードのキーはテストデータ、ライブモードのキーは本番データを読みます）、まずプレビューします。

```bash
npx @waffo/pancake-migrate lemonsqueezy --dry-run
```

書き込む場合は `--dry-run` を外し、Pancake の認証情報を追加します。

```bash
npx @waffo/pancake-migrate lemonsqueezy \
  --merchant-id MER_xxx \
  --private-key ./private.pem \
  --store-id STO_xxx \
  --acknowledge-tax-semantics
```

Lemon Squeezy API は価格が税込かどうかを返さないため、`--acknowledge-tax-semantics` で移行先の税の扱いを確認したことを明示します。Waffo の税設定は変更しません。ターミナルではプロンプトで承認することもできます。ターミナルのない環境（CI など）で実行する場合は、最終確認を省略する `--yes` も追加します。`--yes` は税の確認の代わりにはなりません。キーが複数のストアにアクセスできる場合は `--ls-store-id <id>`、商品のみ移行する場合は `--skip-discounts` を追加します。

## 移行されるもの

### Stripe から

| データ | 移行 |
|---|---|
| Products + Prices | はい — マルチ通貨、画像、説明 |
| Billing periods | はい — `week`→`weekly`、`month`→`monthly`、3 か月ごと→`quarterly`、`year`→`yearly` |
| Webhook endpoints | はい — URL + イベントタイプのマッピング。Pancake は環境ごとに Webhook URL を 1 つだけ保持します。同じ URL のエンドポイントはすべてのイベントをまとめて 1 つにします。URL が複数ある場合は、プロンプトまたは `--webhook-url` で 1 つ選びます（他は一覧表示され、移行されません）。選ばない場合 Webhook はスキップされます（終了コード 1）。`sk_live_` キーではストアの本番 Webhook URL が置き換えられます |
| ストアブランディング | はい — サポートメール + Web サイト |
| Environment | 自動検出 — `sk_test_`→test、`sk_live_`→production。移行元データと Webhook 設定に適用。商品は常に未公開のテスト版 |

### Creem から

| データ | 移行 |
|---|---|
| Products + Prices | はい — 単一通貨、画像、説明 |
| Billing periods | はい — 毎月→`monthly`、3 か月ごと→`quarterly`、毎年→`yearly` |
| Tax categories | はい — `saas`→`saas`、`digital-goods-service`→`digital_goods`、`ebooks`→`ebook`。その他の区分は理由付きでスキップ |

### Dodo Payments から

| データ | 移行 |
|---|---|
| Products + Prices | はい — 未アーカイブで固定価格の単発商品とサブスクリプション。金額は ISO 通貨の最小単位から換算 |
| Billing periods | はい — `payment_frequency_*` の週・月・四半期・年（`subscription_period_*` は使用しません） |
| Tax categories | はい — `saas`→`saas`、`digital_products`→`digital_goods`、`e_book`→`ebook`、`edtech`→`online_course` |
| ID の対応 | 元の ID と税の設定を metadata に保存し、Dodo → Waffo の ID 対応を出力 |
| 契約期間 | metadata のみ — Waffo のサブスクリプションは Dodo の終了日では終了しません |
| 移行元の環境 | 明示指定 — `--environment test` または `--environment live`。どちらでも商品は未公開のテスト版として作成 |

次は理由付きでスキップされます（終了コード 1。`--dry-run` でも同様）: その他の価格・周期・税区分、割引、試用、任意価格、地域別 / 購買力平価価格、アドオン。Webhook、ブランド、クレジット付与は対象外です。

### Lemon Squeezy から

| データ | 移行 |
|---|---|
| Products + Prices | はい — 販売可能なバリアントごとに 1 商品、名前は `商品名 - バリアント名`（バリアントのない商品は商品名のみ）。ストア通貨での現在の価格。HTML の説明はプレーンテキストに変換 |
| Billing periods | はい — 1 週→`weekly`、1 か月→`monthly`、3 か月→`quarterly`、12 か月または 1 年→`yearly` |
| Tax categories | はい — `eservice`→`digital_goods`、`ebook`→`ebook`、`saas`→`saas` |
| 割引コード | はい — 同じコード（大文字で保存）の Pancake クーポンとして作成: 割合または固定額、once / repeating / forever、利用上限、有効期限、対象商品。ストア全体の割引は移行した商品のみに適用され、移行先ストアの既存商品には適用されません。商品の後に、使用する Pancake API キーの環境に作成し、読み戻しで検証。利用回数はゼロから数え直し |
| 移行元の環境 | キーで決定 — テストモードのキーはテストデータを読みます。テスト / ライブどちらのキーでも商品は未公開のテスト版として作成 |

次は理由付きでスキップされます（終了コード 1。`--dry-run` でも同様）: 下書きの商品・バリアント・割引、販売可能なバリアントのない商品、税コードを変換できないバリアント、無料のバリアント、任意価格、無料のリードマグネット、段階 / パッケージ / 従量課金、初期費用、無料トライアル、その他の課金周期、期限切れまたは開始前の割引、3〜32 文字の英数字とハイフン以外のコード、重複コード（大文字と小文字を区別しない）、未移行バリアントに適用される割引、月額以外のプランに適用される repeating 割引（Pancake は月ではなく課金周期で数えます）。ライセンスキーとファイル配布は対象外です。

## 移行されないもの {#what-does-not-migrate}

これらは意図的なものです。それぞれの対処方法は次のとおりです。

| 移行されないもの | 理由 | 対処 |
|---|---|---|
| アクティブなサブスクリプション | サブスクリプションは顧客の銀行との稼働中の課金承認であり、決済処理事業者間でコピーできません | 既存の購読者は Waffo Pancake の [チェックアウト](/ja/guides/checkout-session) で再購読します。移行期間中は旧来と新規の決済処理事業者を並行運用してください。 |
| 顧客データ | 初回購入時に自動作成されます | 不要 — 顧客は最初の Pancake 支払い時に作成されます |
| 支払い方法 | PCI 準拠 — カードデータは元の決済処理事業者から外に出ません | 顧客はチェックアウトで支払い情報を再入力します |
| クーポン / プロモーションコード | Lemon Squeezy からのみ移行されます（上記参照）。Pancake はクーポンとプロモーションコードをネイティブにサポートしています | その他は Pancake で作成し直してください — [割引とプロモーション](/ja/guides/discounts)を参照 |
| チェックアウトのテーマカラー | Stripe は API でこれらを公開していません | [Dashboard → Settings → Checkout](https://pancake.waffo.ai/merchant/dashboard) で設定してください |

## 移行後

<Steps>
  <Step title="カタログを確認">
    **Dashboard → Products** を開き、価格・課金周期・画像が正しく移行されたか確認します。
  </Step>
  <Step title="本番に公開">
    移行した商品は未公開のテスト版です。各商品を [公開](/ja/integrate/skill) して本番稼働させます。
  </Step>
  <Step title="チェックアウトを接続">
    アプリを Waffo Pancake の [チェックアウトセッション](/ja/guides/checkout-session) と [Webhook](/ja/guides/webhooks) に向けます。
  </Step>
  <Step title="並行運用してから切り替え">
    既存の購読者がそれぞれの更新タイミングで移行する間、旧来の決済処理事業者を稼働させたままにします。Pancake チェックアウトが稼働したら、旧来の決済処理事業者での新規登録を停止します。
  </Step>
</Steps>

<Tip>
移行後に統合を構築しますか？ [Waffo Pancake Skill](/ja/integrate/skill) は、チェックアウト・Webhook・サブスクリプション向けの正確な `@waffo/pancake-ts` ワークフローを AI コーディングエージェントに提供します。
</Tip>
